# Превключване на pdktuning.com към новия сайт

Пускането е на **два етапа**. Старият сайт работи и през двата — той остава
пазителят на базата, каталога и входа на дилърите. Нищо не се мигрира.

| | адресът на новия сайт | `www.pdktuning.com` | източникът на каталога |
|---|---|---|---|
| **етап 1** | `new.pdktuning.com` | старият сайт | `www.pdktuning.com` |
| **етап 2** | `www.pdktuning.com` | новият сайт | `catalog.pdktuning.com` |

Разликата в кода е **само стойността на един ключ** — `LEGACY_ORIGIN`. Затова
етап 1 е истинска проба на етап 2, а не негово подобие.

---

## Етап 1 — сайтът застава на `new.pdktuning.com`

### Какво трябва да се направи

Един DNS запис в зоната `pdktuning.com`:

```
Име:      new
Тип:      CNAME
Стойност: new-pdk.pages.dev
Proxy:    включен
```

Записът **заменя** днешния, който сочи сървъра със стария Astro сайт.

В Pages проекта `new-pdk` се добавя `new.pdktuning.com` като custom domain.

### Ключове в средата на Pages

```
LEGACY_ORIGIN = https://www.pdktuning.com
```

Това е всичко, което включва каталога и портала. `www` още е техният сайт,
затова е и източникът — нищо не се пипа от тяхна страна.

**`PUBLIC_INDEXABLE` НЕ се задава на този етап.** Сайтът остава `noindex`:
`new` и `www` биха показвали едно и също съдържание под две имена и биха се
били за едни и същи думи, а по-силният адрес е техният.

### Билдът

```bash
npm run deploy:etap1
```

Адресът се подава при билда (`PUBLIC_SITE_URL`), защото канониклите и картата
на сайта го четат. Зашити на `www` през етап 1, те биха сочили СТАРИЯ сайт —
тоест всяка наша страница би казвала „истинската съм аз, ама другаде“.

## Етап 2 — сайтът поема `www`

Прави се отделно, след като етап 1 е стоял и е бил гледан.

### Нов запис `catalog.pdktuning.com`

Чак сега старият сървър се нуждае от собствено име: след като `www` сме ние,
работникът не може да чете каталога от `www`, защото ще пита сам себе си.

```
Име:      old
Тип:      същият като днешния запис за www
Стойност: същата като днешния запис за www
Proxy:    включен
```

Проксито трябва да е включено — директният произход е със самоподписан
сертификат, изтекъл 2021.

**Виртуалният хост трябва да отговаря и на `catalog.pdktuning.com`** — препредадената
заявка стига до произхода с `Host`, равен на новото име. Проверено.

### Проверка, преди да се пипа `www`

```
curl -sSI https://catalog.pdktuning.com/bg/login
```

Очаква се `200`. Ако не мине, не се продължава — иначе входът на дилърите спира.

### Превключване

```
www  CNAME  new-pdk.pages.dev   Proxy: включен
@    CNAME  new-pdk.pages.dev   Proxy: включен
```

Средата се сменя на `LEGACY_ORIGIN=https://catalog.pdktuning.com` и се добавя
`PUBLIC_INDEXABLE=true`. Билдът минава без `PUBLIC_SITE_URL` (по подразбиране
е `www`).

## Какво се случва с адресите

| Адрес | Кой го обслужва |
|---|---|
| `/`, `/uslugi/`, `/tseni/`, `/katalog/`… | новият сайт |
| `/bg/`, `/en/` | 301 към новата начална |
| `/bg/about-us`, `/contact`, `/privacy-policy` | 301 към новите страници |
| `/bg/tuning` и двете му подстраници | 301 към услугите |
| `/bg/bmw`, `/en/audi`… (110 марки) | 301 към новия каталог |
| `/bg/bmw/3-series-51/…` (~5 500 адреса) | **старият сайт, без промяна** |
| `/bg/login`, `/bg/sign-up`, качването | **старият сайт, без промяна** |
| `/images/`, `/js/`, `/css/`, `/vendor/`, `/uploads/`, `/storage/` | **старият сайт, без промяна** |

Заявките към стария сайт се препредават с метода, заглавките и тялото си.
Сесийната бисквитка минава без `Domain`, тоест залепва за новия адрес и входът
на дилърите работи както днес. Проверено: GET 200, POST 200, `PHPSESSID` наред.

## Връщане назад

Записите се връщат на предишните си стойности. Старият сайт не е спирал и поема
веднага. Разпространението на Cloudflare е в рамките на минута.

## Проверките

```bash
npm run preflight          # етап 1: готово ли е всичко
npm run redirects          # целият стар sitemap през новия сайт
npm run postflight         # етап 1, след смяната — срещу живия адрес

npm run preflight:etap2    # същото за етап 2
npm run postflight:etap2
```

`preflight` излиза с грешка, докато има нещо, което спира. Разграничава „спира“
от „ще излезе празно“: празният ЕИК не е причина да не се пуска сайтът,
липсващият DNS запис е.

`redirects` взима `sitemap.xml` на стария сайт и пуска всеки адрес през новия.
Гледа **съдържание, не статус** — старият връща 200 и началната си страница за
несъществуващ адрес. С `--all` минават всичките 5 586 адреса, с `--csv` излиза
файл.

Преди смяната се пуска срещу местен работник:

```bash
npx wrangler pages dev dist --port 8788 \
  --binding LEGACY_ORIGIN=https://www.pdktuning.com
npm run redirects
```

Последно измерено така: **117 пренасочени, 3 357 запазени при стария сайт,
0 счупени.**
