# `site/` — новият сайт на pdktuning.com

**Това е ДРУГ сайт от този в корена на хранилището.** Двата живеят тук един до
друг, но не се строят заедно, не се деплойват заедно и не си делят нищо.

| | коренът на repo-то | `site/` (тук) |
|---|---|---|
| какво е | Astro сайт с 30 885 страници от изнесен каталог | новият сайт, 183 страници |
| къде отива | VPS-ът, Docker + nginx | Cloudflare Pages, проект **`new-pdk`** |
| какво го пуска | таг `v*` → `.github/workflows/deploy.yml` | `npm run deploy:etap1` оттук |
| базата | JSON в хранилището | **чете се на живо от стария сайт** |

`site` е в `.dockerignore` — не влиза в образа на стария сайт и не му тежи на
билда.

---

## Какво прави този сайт

183 страници: начална, услуги, цени, каталог на 110 марки, електрически
автомобили, статии, правни. Плюс динамичен слой в `public/_worker.js`
(Cloudflare Worker), който върши четири неща:

1. **Чете каталога на живо** от стария сайт (`/live/*`). Базата НЕ се мигрира и
   НЕ се копира — старият сайт остава единственият ѝ пазител.
2. **Препредава техните пътища** — `/bg`, `/en`, порталът на дилърите,
   статиката. Със същия метод, заглавки и тяло, за да не се счупят ~5 500
   индексирани адреса и входът на партньорите.
3. **Пренасочва 117 стари адреса** към новите им наследници.
4. **Формата и чекаутът** — Resend и Stripe.

Работникът е Cloudflare-specific. Затова този сайт НЕ може да се качи на VPS-а
без да се пренапише целият динамичен слой.

## Адресите НЕ се пишат в кода

Домейните живеят на едно място — `.env.local` (местно) и настройките на Pages
проекта (в облака). При превключването се сменя стойност, не код.

```bash
cp .env.example .env.local     # и се попълва
```

```
BASE_URL           къде стои НАШИЯТ сайт — канониклите, картата, схемите
CATALOG_BASE_URL   откъде се чете каталогът и къде живее порталът
```

`BASE_URL` **няма подразбиране** и билдът спира без него. По-рано тук стоеше
зашито `https://www.pdktuning.com` и празна среда даваше успешен билд с
каноникли към СТАРИЯ сайт — тоест всяка наша страница казваше „истинската съм
аз, ама другаде“. Такъв билд изглежда успешен и се вижда чак когато Google
вече го е обходил.

`npm run check:urls` пази правилото и върви вътре в `npm run check`. Изключени
са само три неща и всяко с причина: съобщенията за грешка (там адресът е
пример за човека), имейлите и текстът в политиката за поверителност, която е
длъжна да назове откъде се четат данните.

**Порталът на дилърите е относителен** — `/bg/login`, не абсолютен адрес.
Работникът го препредава към източника, а `PHPSESSID` се връща без `Domain` и
залепва за нашия домейн. Зашит адрес щеше да е грешен и на двата етапа: на
етап 1 извежда хората извън сайта, на етап 2 сочи `catalog` — вътрешния
произход, който няма нашите заглавки и няма работа пред дилър.

## Пускане

Става на два етапа. Подробно в [`docs/prevklyuchvane.md`](docs/prevklyuchvane.md).

```
етап 1   сайтът застава на new.pdktuning.com, www остава старият
         BASE_URL          https://new.pdktuning.com
         CATALOG_BASE_URL  https://www.pdktuning.com

етап 2   сайтът поема www
         BASE_URL          https://www.pdktuning.com
         CATALOG_BASE_URL  https://catalog.pdktuning.com
```

Разликата в кода е **нула**. Затова етап 1 е истинска проба на етап 2, не
негово подобие.

```bash
npm install
npm run deploy:etap1     # билд с адресите на етап 1 + качване към Pages
npm run preflight        # готово ли е всичко; разграничава „спира“ от „ще излезе празно“
npm run redirects        # целият стар sitemap през новия сайт
npm run postflight       # същото, но срещу живия домейн след смяната
```

### Състояние (16.09.2026)

`new.pdktuning.com` все още сочи към VPS-а, защото CNAME-ът към Pages минава
през IT-то на клиента. Дотогава контейнерът в корена препредава заявките за
това име насам — виж `map $host $to_new_site` в `docker/nginx/nginx.conf`.
Щом записът се направи, препредаването спира да се задейства само.

`catalog.pdktuning.com` вече съществува като запис, но връща **525**:
произходът отказва SSL под това име. Етап 2 не бива да се пуска, докато
`curl -I https://catalog.pdktuning.com/bg/login` не върне 200 — иначе каталогът
и входът на дилърите падат в секундата.

## Ключове в средата на Pages

```
BASE_URL           адресът на сайта (виж по-горе)
CATALOG_BASE_URL   източникът (старото име LEGACY_ORIGIN още се приема)
PUBLIC_INDEXABLE   НЕ се задава на етап 1 — иначе new и www се бият за едни
                   и същи думи, а по-силният адрес е техният
PUBLIC_GA_ID       GA4 маркерът на клиента (G-13T4ZTVM1W) — виж docs/mereneto.md
PUBLIC_GSC_VERIFY  кодът за Search Console, само съдържанието на `content`
PORTAL_URL         по избор: абсолютен адрес на портала. Празно = относителен
RESEND_API_KEY / CONTACT_TO / CONTACT_FROM    без тях формата връща 503
STRIPE_SECRET_KEY + PUBLIC_CHECKOUT=true      вдигат се ЗАЕДНО
```

**Качен ключ не действа, докато не се пусне нов деплой.** Pages чете средата
при билда, не при заявката; 1010 в отговора не е 401.

## Команди

| команда | какво прави |
|---|---|
| `npm run dev` | местен сървър (Astro) |
| `npm run build` | `dist/` |
| `npm run check` | `astro check` + пазачът за зашити адреси |
| `npm run check:urls` | само пазачът |
| `npm run deploy:etap1` | билд с адресите на етап 1 + качване към Pages |
| `npm run preflight` | готово ли е всичко преди DNS-а; `--live` = след смяната |
| `npm run redirects` | целият им sitemap през новия сайт; гледа СЪДЪРЖАНИЕ, не статус |

Динамичното се тества с `npx wrangler pages dev dist --binding КЛЮЧ=стойност`.
**`--env-file` се глътва мълчаливо** от `wrangler pages dev` — ключът не стига
до работника и изглежда, че кодът не работи.

## Какво чака клиента

ЕИК и ДДС, потвърждение на адреса и работното време, потвърждение на цените,
истинският имейл, линковете към PDK Flasher в двата магазина и цените на
33-те електрически модела.

**Празните полета вече НЕ се показват** — редът просто не се рисува и се
появява сам, щом стойността влезе в `src/data/business.json`. Рамките „чака
се“ бяха махнати на 16.09.2026, защото пред посетител четат като недовършен
сайт. Следствието е, че **от сайта няма кой да напомни**: единственото
напомняне е `npm run preflight` и бележките с долна черта в самия
`business.json`.
